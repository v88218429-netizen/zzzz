# WB AI Manager v1.1.4 — управление, контроль и обучение

Локальный центр управления Wildberries в режиме **только чтение**. Система собирает факты из кабинета WB, таблиц, РНП, остатков, рекламы, поиска, карточек, финансов и публичного рынка. Девятнадцать специализированных агентов отвечают за сбор и нормализацию данных; одно управляющее ядро формирует итоговые решения, независимая проверка пытается их опровергнуть, а затем система контролирует фактический результат.

## Главное отличие v1.1

Система больше не должна работать как набор уведомлений. Рабочая цепочка:

`факты → расследование → варианты действий → проверка риска → числовое решение → наблюдение фактического изменения → контроль результата → обучение`

Решение по рекламе строится **для конкретной пары «кампания + nmID»**. Если многотоварная кампания не отдаёт раздельную статистику конкретного товара, повышение ставки блокируется: общие цифры кампании товару не приписываются.

## Что учитывается вместе

- реклама: ставка, расходы, показы, клики, CTR, CPC, заказы, ДРР, поисковые кластеры и рекомендации WB;
- все заказы SKU, включая ускорение спроса и день недели;
- позиции и частотность поисковых запросов;
- цена, СПП и юнит-экономика;
- K2 / ФФ / WB-остатки, долг поставщика и подтверждённые поступления;
- жизненный цикл заказа `created → buyout/cancel` по SRID;
- карточка: заполнение, медиа, характеристики и воронка;
- отзывы, вопросы, возвраты, удержания и качество исполнения;
- конкуренты и публичная выдача WB;
- история собственных решений и фактических изменений.

## Когортная аналитика

Свежие заказы не сравниваются напрямую с выкупами той же календарной недели. Система измеряет реальный срок созревания заказов по каждому SKU и отдельно хранит:

1. текущий спрос;
2. ещё созревающую когорту;
3. зрелый финансовый результат.

Решение не признаётся успешным только потому, что после него выросли заказы. Для долгого горизонта нужна достаточно зрелая когорта и фактическая экономика именно этого периода.

## Реклама

Финальная карточка должна отвечать числами:

- текущая ставка;
- рекомендуемая ставка;
- допустимый расход до следующей проверки;
- фактический и экономически допустимый ДРР;
- текущий и прогнозный запас;
- динамика заказов, трафика, позиции и частотности;
- зрелость заказов;
- точное условие следующего пересмотра.

При нерешённом критическом ограничении система синхронно замораживает и текст решения, и ставку, и лимит расхода. Не допускается ситуация, когда текст говорит «не повышать», а рядом остаётся повышенная числовая цель.

## Контроль собственных решений

Каждая materially изменившаяся рекомендация сохраняется в историю. Фактическое изменение ставки/цены/медиа фиксируется отдельно. Решение считается выполненным для обучения только когда наблюдаемое действие действительно совпало с рекомендацией агента. Решение «оставить ставку как есть» тоже фиксируется после повторного подтверждения неизменной ставки. Чужое ручное изменение не засчитывается как успех или ошибка агента, а любое последующее вмешательство прерывает оценку предыдущего решения.

После применения создаются контрольные точки: **1 час, 3 часа, 24 часа, 7 дней и 14 дней**. Если тип решения изменился, но объект тот же, контроль продолжается по той же паре «кампания + товар».

## Проверка новых правил

Исторические РНП и NASYR используются как контекст и полигон для проверки правил. Они не считаются доказательством причинности сами по себе. Новая закономерность должна пройти историческую проверку, а после включения — подтверждение на фактически применённых действиях.

## Редактор правил

В интерфейсе есть раздел **«Правила управления»**. Бизнес-пороги применяются без перезапуска: допустимый шаг ставки и расхода, требования к выборке, интервалы повторной проверки, целевое покрытие запасов, окна тренда и другие параметры. Техническую защиту и режим только чтения через интерфейс отключить нельзя.

## Самообновление

После установки приложение проверяет стабильный канал обновлений. Перед заменой кода создаётся резервная копия, проверяются контрольные суммы и запуск; при ошибке выполняется откат. Пользовательские `.env`, база `data/`, `config/catalog.csv` и `config/watch_queries.yaml` патчами не заменяются.

## Безопасность

- `FORCE_READ_ONLY=true`;
- любые записи в Wildberries заблокированы независимо от пользовательских настроек;
- интерфейс не содержит кнопок применения ставок/цен/карточек;
- недостающие данные превращаются в явное ограничение, а не в догадку;
- ошибка одного источника не должна останавливать остальные контуры.

## Запуск

Дважды нажми `START_WB_AI_MANAGER.command` и выбери **1 — АВТО**.

## Проверка сборки

```bash
python -m pytest -q
python -m compileall -q src scripts
node --check src/wb_control_center/ui/dashboard.js
bash -n START_WB_AI_MANAGER.command scripts/launch/*.command scripts/*.sh
python scripts/update_smoke.py
```

Перед публикацией v1.1 дополнительно выполняются полный прогон всех 19 агентов, HTTP-проверка интерфейса и API, миграция базы v1.0 → v1.1 и проверка механизма обновления/отката.
