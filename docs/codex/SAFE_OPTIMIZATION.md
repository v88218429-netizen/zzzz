# Безопасная оптимизация Codex, WB и автоматизаций

## Принципы внедрения

- Production first: не нарушать действующие FBS, РНП, рекламу, отчёты, мосты Sheets, Google Apps Script и GitHub Actions.
- Новые инструкции и Skills включаются только при релевантной задаче. Не добавлять огромные системные промпты.
- Не менять модель, тариф, API-ключ, способ авторизации или бизнес-порог автоматически.
- Использовать уже существующие Caveman, Search First, Graphify, Headroom, навыки WB и DUSHA Evidence Gate; не создавать конкурирующий источник истины.
- Сначала маленький PR и тесты; только затем проверенный live-эффект. Статус в репозитории не равен статусу production.

## Что добавляет этот PR (без вмешательства в runtime)

1. Три навыка Codex в стандартном проектном каталоге `.agents/skills/`:
   - `wb-seller-audit` — подключает проверенные существующие навыки WB по запросу.
   - `wb-product-image-qa` — обеспечивает проверку физических характеристик товара и отдельных WB-слайдов.
   - `safe-wb-release` — фиксирует правила безопасного выпуска.
2. `scripts/codex_ci_audit.py` — независимый отчёт по существующим GitHub Actions, только чтение.
3. `tests/test_codex_ci_audit.py` — локальные проверки скрипта.

## Локальный Codex на Mac

На Mac 6 ноября 2026 был добавлен официальный read-only OpenAI Docs MCP:
`codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp`.

Проверка локальной TOML-конфигурации подтвердила, что сервер подключён, а существующие Headroom, модель `gpt-6-luna` и уровень `high` сохранены. Бэкап: `~/.codex/config.toml.backup-pre-docs-mcp-20261106`.

**Важно:** локальный `~/.codex/config.toml` намеренно не коммитится в GitHub. Изменение на Mac не является глобальным изменением подписки ChatGPT.

## Ближайшие этапы после базовых проверок

| Этап | Действие | Обязательный критерий |
|---|---|---|
| A | Контроль контекста через уже доступные Headroom, Graphify, адресные Skills | Качество информации и ограничения сохраняются |
| B | Снижение избыточных запусков CI | Проверить обязательные статусы PR и отсутствие пропущенной проверки |
| C | Разнести лёгкий опрос и тяжёлый анализ AI Video Monitor | Реальная транскрипция и запись в Google Sheets не нарушены |
| D | Ввести эталонные тестовые случаи для WB-решений и инфографики | Факты, размеры и денежные ограничения совпадают с эталоном |
| E | Проверить модели/режимы на реальных тестах | Фиксировать качество, стоимость, задержку; менять только после оценки |
| F | Codex SDK, дополнительные субагенты и API-оптимизации по потребности | Встроить в существующий DUSHA, не дублировать его управление |

## Зачем не включать всё сразу

- `/compact`, Skills и короткие логи помогают уменьшать контекст, но чрезмерная компрессия может потерять важные детали.
- Более простая модель дешевле не для всех задач; критичные решения требуют тестов.
- Параллельные агенты могут расходовать больше ресурсов.
- Prompt Caching / Batch API относятся к API и не повышают лимиты подписки ChatGPT.
- `concurrency.cancel-in-progress: true` допустим для заменяемых CI-проверок, но опасен для учёта заказов и денег.
- `paths` в GitHub Actions нельзя внедрять вслепую, если статус проверки обязателен для слияния.

## Как проверить этот этап

```bash
python3 scripts/codex_ci_audit.py --json
python3 -m unittest discover -s tests -p 'test_codex_ci_audit.py' -v
```

Ни одна команда выше не изменяет репозиторий, рекламные ставки, заказы, внешние таблицы или конфигурацию Codex.
