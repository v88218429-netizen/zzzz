# Первичная диагностика расходов GitHub Actions — 2026-11-06

Исходное наблюдение через GitHub API (не подтверждённая стоимость): в основном репозитории **76 файлов workflows** и **10 284 записей о запусках** к моменту проверки. Это суммарная история, не месячный расход.

Примеры потенциального повторения работы:

- \`wb-ai-manager-release-verify.yml\`: два последовательных полных \`pytest -q\` в чистых копиях, что может быть намеренной проверкой воспроизводимости.
- \`wb-query-manager-ci.yml\`: запускается на PR в \`mainggg\` без фильтра путей и выполняет целевые тесты.
- \`wb-ai-manager-targeted-tests.yml\`: уже использует \`cache: pip\` и отменяет устаревшие CI-запуски. Сохранять эту защиту.
- \`wb-optimizer-acceptance-ci.yml\`: дополнительные проверки тестов оптимизатора.
- \`ai-video-monitor-autonomous.yml\`: для непустого/обычного запуска устанавливает Ollama и скачивает \`qwen2.5:1.5b\` до обработки. Прежде чем оптимизировать, изучить условия пустого запуска, доступность/кеш модели и проверить непрерывность обработки новых видео.
- \`wb-github-runtime.yml\`: планируется каждые 10 минут. \`cancel-in-progress: false\` и блокировки runtime могут быть необходимы: не отменять бизнес-запуски ради экономии.

Это **кандидаты на измерение, не доказательство перерасхода**. До изменения workflow:

1. Получить реальную статистику длительности, ошибок и пропусков, а также требуемые статусы веток.
2. Сохранить исходные workflows и настройки расписания.
3. Точно определить, какие проверки безопасно объединять, а какие требуются для выпуска.
4. Отключение/изменение — отдельным PR с проверкой на тестовом изменении.
5. Сравнить пропуски и длительность до/после; откатить при регрессии.

Для безопасного инвентаризационного отчёта выполнить:

\`\`\`bash
python3 scripts/codex_ci_audit.py --json
\`\`\`

Скрипт только читает локальные \`.github/workflows\`, не связывается с внешними сервисами и не знает API-ключей.
